# v2.9.0 EXACT GEOMETRY

v2.9.0 extends the deterministic family layer with an exact geometry engine for the radical-axis / angle-bisector integer-triangle family exposed by AIMO3 reference Problem 3.

## Main change

For the matched geometry family the pipeline no longer asks the 4B LLM to guess an integer triangle. It performs the following fail-closed chain:

1. Recognize the full geometric structure, not just generic `triangle/circle` words.
2. Use the radical-axis reduction: `AB*AX = AE*AC`, hence `AX=AC` because `AE=AB`.
3. Reduce the condition to the internal angle-bisector cevian satisfying `AD=AB`.
4. Use angle-bisector theorem + Stewart to derive exactly

   `a^2*b = (b+c)^2*(b-c)`

   for `a=BC, b=CA, c=AB`, `c<b`.
5. Enumerate integer triples by increasing perimeter, checking triangle inequality, acuteness, labeling, and the exact integer relation.
6. Require uniqueness at the first feasible perimeter.
7. Independently verify `AD^2=AB^2`, equal powers at `A`, and the coprime parameterization before exposing the candidate.
8. Only then normalize to the requested modulus and emit `FAMILY_EXACT`.

The runtime source does **not** contain the benchmark answer or the benchmark side triple. The answer is generated by the exact reduction/search. Tests may contain expected values because they are regression tests.

## Expected reference behavior

`--engine-only --all --benchmark-reference` on `AIMO3_Reference_Problems.pdf`:

- P1: unsupported by deterministic family layer (falls back to semantic compiler in full mode)
- P2: exact deterministic engine
- P3: exact geometry engine
- P4: exact functional-equation engine
- P5: exact tournament engine
